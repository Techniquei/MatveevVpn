# Проверка обновления с 1.3.5

Проверено 7 октября 2026 года: опубликованная 1.3.5 и рабочий код на базе
1.4.0-beta.5 с изменениями интерфейса и правил маршрутизации.
Stable-релиз не опубликован; его конечный DMG ещё не проверен.

## Совместимость

- Опубликованный DMG 1.3.5 сверён с SHA-256 из GitHub Release.
- Идентификатор приложения `com.matveev.vpn`, путь настроек, схема 2,
  публичный ключ Sparkle, Sparkle 2.9.6 и минимум macOS 13 совпадают.
  Обе версии предназначены для Apple Silicon.
- Подписка, выбранный сервер, домены, режим маршрутизации, выбранные пресеты,
  блокировка рекламы и желаемое состояние подключения сохраняются.
- Системный компонент 1.3.5 имеет версию 12; рабочая версия использует 27.
  После замены приложения обновление компонента запускается автоматически,
  с запросом прав администратора. При отмене или ошибке попытка повторяется
  при следующем запуске приложения; отдельной кнопки Update нет.
  При неудачной установке предусмотрено восстановление предыдущего компонента.
- Пользовательские правила по именам и путям приложений удалены намеренно.
  После применения новой конфигурации в Selective такой трафик идёт напрямую,
  если его не покрывают домены или пресеты. После сохранения настроек старые
  поля приложений больше не записываются.

## Исправления по результатам проверки

- Компоненты до версии 14 получают прежнюю команду `action token`, новые —
  `action token expiry`. Это позволяет отключить VPN и сбросить настройки
  до обновления компонента 12; раньше третье поле делало старый токен невалидным.
- Удалена очистка доменов по совпадению со старым встроенным списком.
  Она могла стереть пользовательский список после удаления полей приложений.
- Релизный workflow теперь проверяет обнаружение как stable, так и beta
  с исходной версии 1.3.5/build 1305.

## Автоматические проверки

- Настройки, созданные настоящим кодом тега `v1.3.5`, загружаются и сохраняются
  в обоих режимах и состояниях подключения; идентификатор сервера не меняется.
  Проверены восстановление журнала и сохранение старого списка доменов.
- Проверяются двухпольный и трёхпольный протоколы команд. Текущий клиент также
  успешно выполнил Disconnect и Reset с настоящим controller.sh из тега 1.3.5
  в изолированной службе без активного туннеля.
- Автоматическое обновление при запуске проверено с сохранением подписки,
  сервера и желаемого состояния подключения. Проверены отмена, повторная попытка
  при следующем запуске и отсутствие запроса для совместимого компонента.
- На опубликованном appcast 1.3.5 не получает beta без согласия пользователя;
  при включённой beta обнаруживается build 1417.
- На локальном тестовом appcast будущий stable 1.4.0/build 1418 обнаруживается
  при выключенной и включённой beta. Проверен и настоящий код обновлятора из
  тега 1.3.5. Эти тесты запрашивают только информацию об обновлении.
- `Scripts/validate.sh` включает проверки конфигурации, DNS, маршрутизации,
  первого запуска, интерфейса и отката установщика в изолированном user launchd.
  Полный прогон после исправлений завершился результатом `validation: ok`.

Локальный appcast для будущего stable изменён только для проверки обнаружения.
Он не подтверждает подпись, загрузку и установку конечного stable-архива.
Тесты установщика используют изолированные пути и не создают настоящий VPN-туннель.

## Перед публикацией stable

1. Выставить окончательную stable-версию и build выше 1418, например
   `1.4.0` / `1419`, в приложении и сборочном скрипте.
2. Оформить заметки именно для этого релиза, включая удаление правил приложений
   и необходимость обновить системный компонент.
3. Собрать конечный DMG, подписать его прежним EdDSA-ключом и проверить appcast
   без канала beta. Инструкции: [RELEASING.md](RELEASING.md).
4. На тестовом Mac или VM выполнить настоящее обновление установленной 1.3.5
   через Sparkle: замена приложения, закрытие старого процесса, запуск новой
   версии и сохранение подписки/сервера/настроек.
5. Проверить автоматическое обновление компонента 12 до 27, отмену авторизации
   и повторную попытку при следующем запуске,
   подключение TLS и REALITY/XHTTP, смену серверов, Selective/All Traffic,
   сон/пробуждение и восстановление исходного DNS после отключения.

Успешное обнаружение обновления и автоматические проверки дают основание
готовить stable. Готовность к публикации подтверждает проверка конечного архива
и установленного приложения.
